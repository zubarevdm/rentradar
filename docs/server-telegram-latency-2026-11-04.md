# Исправление задержек Telegram на VPS — 4 ноября 2026

Работающая версия сервера: `/opt/rentradar`, коммит `b3509b4`.
Она отличается от старой локальной копии проекта; исправление применено к
актуальному серверному `src/rentradar/tg.py`, а не поверх старого исходного кода.

## Причина и воспроизведение

Повторное использование HTTPS-соединения с Cloudflare relay на текущем сетевом
маршруте приводит к зависанию примерно каждого седьмого запроса. В сравнительном
тесте getMe обычное соединение дало 7 тайм-аутов на 50 запросов; новое соединение
на каждый запрос — 0 на 50. Точный сетевой узел, вызывающий зависание, не установлен.
Стандартное ожидание aiogram составляет 60 секунд, а для поллинга с timeout=10
становится 70 секунд. Это объясняет длительные паузы команд и ответов.

## Изменение

В `make_bot`, после создания `AiohttpSession`, только при заданном
`settings.telegram_api_base` добавлено:

```python
if settings.telegram_api_base:
    session._connector_init["force_close"] = True
```

Теперь relay использует новое соединение на каждый HTTP-запрос. Прямой транспорт
сохраняет повторное использование соединений. Это обращение к внутренней настройке
aiogram покрыто интеграционным тестом на реальном локальном HTTP-сервере;
при обновлении aiogram следует запускать `tests/test_tg_transport.py`.
Цена изменения — дополнительное TLS-соединение на каждый запрос.
