# Меню Telegram Desktop и качество фотографий — 25.10.2026

## Найденные причины

Меню было обычной reply-клавиатурой в некоторых ответах; Telegram Desktop мог
показывать ленту без неё. При отправке альбомов reply_markup вообще не передавался:
в Bot API у sendMediaGroup этого параметра нет. Поэтому под объявлениями не было
даже кнопки источника, которая уже была предусмотрена для одиночного фото.

Для объявления со скриншота подтверждено разрешение исходного файла из БД:
**208×208, JPEG, 8371 байт**. Это миниатюра Авито, а не результат уменьшения ботом.
У записи не было сохранённых полноразмерных фото или завершённого обогащения.
Два диагностических запроса к странице источника, напрямую и через уже настроенный
системный прокси, получили **HTTP 439**. Прокси проекта при этом не изменялся;
дополнительных запросов в рабочий алгоритм не добавлено. Персональные данные,
адрес, ссылка объявления и подписанные URL фото в отчёт не включены.

## Реализация

- Главные действия представлены inline-кнопками, видимыми в сообщении: поиск,
  фильтры, статус, подписка, приглашение, поддержка. `/menu` показывает их заново.
- Callback использует ID нажавшего пользователя, а не ID бота — автора сообщения.
- Startup-hook настраивает нативное меню команд для личных чатов. Расписания и
  порядок сборщиков не менялись.
- К альбому после доставки прикрепляются кнопки источника и, в личной рассылке,
  «☰ Меню». При ошибке/флуд-лимите повторяется только редактирование кнопок;
  уже доставленные медиа повторно не отправляются.
- Из уже полученной разметки Авито выбирается крупнейший реальный вариант каждого
  фото: разные разрешения, обычный/экранированный JSON, srcset карточек. Ссылки не
  конструируются из подписанных URL; фото не обрезаются и не увеличиваются.
- Исходные байты загружаются без повторного JPEG-сжатия. Размер JPEG/PNG читается
  без декодирования, только для распознавания маленьких превью. Если доступны
  только они, текст ссылки честно ведёт к полным фото в объявлении. Денежные
  условия, источник, порядок и лимит фотографий сохраняются.

## Проверки

До правок: 203 теста прошли, 10.71 с; mypy — 76 исходных ошибок в 13 файлах.
После правок: **217 passed**, 10.67 с; Ruff проходит; mypy — те же 76 ошибок,
новых диагностик относительно baseline нет. `git diff --check` проходит.

Добавлены проверки кнопок альбома и приватной навигации, выбора правильного
пользователя, регистрации штатного меню, ошибок кнопок без дублей альбома,
фотографий разных размеров, srcset, JPEG 208×208 и 1280×960, сохранения исходных
байтов и обозначения маленьких превью. Тесты используют временные БД и моки.

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q --basetemp=.test-ui/full -p no:cacheprovider
.\.venv\Scripts\ruff.exe check src tests scripts
.\.venv\Scripts\mypy.exe src/rentradar
.\.venv\Scripts\python.exe scripts/verify_change_scope.py --photo-fixes
git diff --check
```

`--photo-fixes` разрешает только две функции фото и импорт их помощников в
коллекторе Авито. Остальные функции, включая сеть и нормализацию, проверяются
по AST; платежная часть parse_detail сверяется отдельно. Дефолтный строгий
режим проверки предыдущего задания сохранён. Сборщики других площадок,
конвейер, скоринг, хранилище объявлений, интервалы, прокси, ограничения рассылки,
расписания и startup_jobs не изменены.

## Границы результата

Резкость отсутствующего оригинала восстановить нельзя. Для примера со скриншота
источник блокирует доступ к оригиналу; повышение качества возможно там, где
исходная разметка предоставляет крупный вариант. Старые уже отправленные сообщения
не переписываются, а сохранённые маленькие фото не заменяются выдуманными URL.
Расположение и масштаб плиток альбома определяет Telegram. Полный type check
остаётся неуспешным из-за существующих ошибок mypy.

Источники по Bot API: [sendMediaGroup](https://core.telegram.org/bots/api#sendmediagroup),
[editMessageReplyMarkup](https://core.telegram.org/bots/api#editmessagereplymarkup),
[setChatMenuButton](https://core.telegram.org/bots/api#setchatmenubutton).


## Применение

Бот перезапущен с прежним launcher и системным прокси; перед запуском сохранена
и проверена резервная копия БД. В журнале подтверждены успешные SetMyCommands,
SetChatMenuButton и начало polling, без traceback или конфликта polling.
Тестовые объявления пользователям не отправлялись. Дополнительно остановлен
параллельный plain-экземпляр этого же бота; родительский терминал не изменялся.
Открыть новое меню вручную можно командой `/menu` или `/start`.
