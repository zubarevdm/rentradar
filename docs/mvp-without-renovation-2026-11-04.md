# MVP без выбора ремонта и анализа фотографий

Установлено на VPS 4 ноября 2026, около 01:16 по Москве.
Основа — фактическая серверная версия b3509b4 и ранее установленное исправление
Telegram-транспорта. Основной локальный src старее сервера; актуальные исходники
и тесты находятся в `.deployment/live-source`. Переносимый diff сохранён рядом
в `mvp-without-renovation.patch`. На GitHub изменения не опубликованы.

## Поведение

- Цепочка: комнаты → цена → метро → время до метро → комиссия → частота → новые/все.
- Удалены состояние, клавиатура, сохранение и отображение выбора ремонта.
- Кнопка «Назад» из комиссии ведёт к времени до метро.
- Старые кнопки ремонта объясняют, как начать новый поиск.
- Ремонт больше не участвует в персональном подборе; старое поле БД оставлено
  только для совместимости, приложение его не читает и записывает NULL.
- Vision отключён по умолчанию и явно в серверной конфигурации. Сохранённый ключ
  не запускает анализ. Задание Vision не регистрируется.
- Публичные публикации не требуют анализа, определённого ремонта или оценки
  красоты, сортируются по обычному скорингу. Старые оценки красоты не влияют на
  скоринг (нейтральный вклад сохраняет прежнюю шкалу порогов).
- Известные отметки подозрительных объявлений, проверки текста, цены, фотографий
  и остальные правила продолжают работать. Старые выбранные фотографии сохранены.

## Проверка

399 тестов прошли в отдельной папке VPS. Проверены прямой/обратный ход настройки,
сохранение остальных условий старого фильтра с ремонтом в БД, отключение
анализатора при наличии ключа и публикация непроанализированных квартир.
После установки подтверждены совпадение файлов с проверенной версией,
`vision=off`, отсутствие шага ремонта и активная служба без перезапусков.

В БД сохранены 2 фильтра. Ненулевых ограничений ремонта на момент обновления
не было. Остальные поля всех фильтров сверены до и после и не изменились.

Резервная копия исходников, настроек и согласованная копия SQLite:
