# Доставка Циана и повторные записи user_sent

Установлено на VPS 4 ноября 2026 около 01:41 по Москве.
Актуальный исходный код: `.deployment/live-source`; основной локальный src
старее сервера. Diff: `delivery-fix-2026-11-04.patch`. Изменения не опубликованы
на GitHub. Новый тест: `.deployment/live-source/tests/test_delivery_idempotency.py`.

Фотографии Циана собирались: 1595 из 1596 объявлений в БД имели фото. Скачивание
с CDN сервером работало (HTTP 200, WebP). Загрузка файлов через relay зависала,
после чего publisher переходил к тексту. Фото по URL дошло за 0,39 с; альбом
трёх фото отклонён Telegram с WEBPAGE_CURL_FAILED на третьем снимке; первые два
дошли за 0,28 с. Это проверка конкретного объявления, не гарантия для всех CDN URL.

Для Циана publisher теперь сначала отправляет первые два URL, затем один URL,
затем пробует скачать/конвертировать первые два фото и использует прежние запасные
варианты. При недоступности всех снимков текстовый запасной вариант остаётся.
Остальные фото доступны по ссылке на объявление. Gemini выключен.

mark_sent заменён атомарным SQLite UPSERT по (user_id, content_key). Повторная
запись не вызывает IntegrityError. Успешная доставка не понижается до пропуска,
время первой успешной доставки сохраняется. Пропущенная запись может стать
доставленной. run_due сериализован asyncio.Lock, чтобы стартовый и плановый
проходы одной службы не отправляли одновременно одни квартиры.

402 теста прошли, включая конкурентные повторные отметки и резервную загрузку
изображений. Реальные тесты отправки сделаны в чат администратора.
